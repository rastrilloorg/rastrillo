这里印出来的是浅色那一套值。深色那一套是在同一个文件里手写的——从不靠反转——而 ui/contrast_test.go 会把两套里每一对有记录的颜色都压在 WCAG 2.2 AA 的底线上：文字 4.5:1，控件边框 3:1。色块本身用 var() 上色，所以它们跟着你正在看的方案走，在深色模式下不会和印出来的值对上。

模板片段

ui 提供的每一个模板片段，都放在真实页面会让它处于的状态里。每个片段只接受一个数据值，用 dict 就地构造。表单放在有内边距的 rst-box 里，行放在 rst-list 里，因为这些片段就是这么假定的——见下面「类惯用法」里的两条规则。有一点画廊无能为力：page-header 和 error-page 各自带一个 h1，所以这一页上有好几个，而真实页面只该有一个。

样例里的内容在每一页上都保持英文：这些样例中的名字、路由和标签都是替身，翻译它们会让人以为框架本身带着那些词。外壳和模态框的演示正好相反——它们在扮演一个真实的应用，所以它们的框架说的是你选的语言。

类惯用法

那些片段做不到的形状，因为它们要包住只有调用方才知道的内容：分节卡片、数据网格、折叠菜单、外壳自己的框架。tokens.css 提供类，标记由应用来写。下面这些正是 ui.Styleguide 返回的样例，也就是 ui 的测试拿来对着 tokens.css 检查的样例——请从这里复制。

box

带内边距的分节卡片，以及坐在它外面的那个标题。

哪张卡片是哪一种

rst-list 和 rst-card 故意没有内边距：它们装的是一串行，每行自己有内边距。把表单、段落、一排链接或任何不是行的东西直接塞进去，就会紧贴着边框渲染——文字碰到边缘就是那个信号。给任意内容用的有内边距卡片是 rst-box，它的标题是放在它前面的兄弟节点 rst-box-head。

页面框架本身。rastrillo new 会把其中一个写成 templates/layout.html；页面填进内容的空洞，并按需要覆盖某些框架块。下面每个演示都是一整页，有自己的网址——打开一个，在全宽下才看得出 sidebar 的导航栏和 topbar 的页脚是真有地方。

column
