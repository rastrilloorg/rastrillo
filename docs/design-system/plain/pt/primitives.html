Primitivas de interface

As formas que um componente não pode ser, porque envolvem um corpo que só quem chama conhece: o cartão de secção, a grelha de dados, o menu de revelação e a moldura própria dos invólucros. O tokens.css traz as classes e a aplicação escreve a marcação. Tudo o que está abaixo é exatamente o exemplo que ui.Styleguide devolve, que é o exemplo que os testes de ui confrontam com tokens.css.

As ligações aqui não estão ativas

Ligações inativas; o código do exemplo é fornecido.

box

O cartão de secção com espaçamento, e o título que fica fora dele.

Qual cartão é qual

O rst-list e o rst-card não têm espaçamento de propósito: seguram uma série de linhas, e cada linha espaça-se a si mesma. Meta lá dentro um formulário, um parágrafo, uma tira de ligações ou qualquer coisa que não seja uma linha e aparece encostado ao contorno — o texto a tocar na borda é o sinal. O cartão com espaçamento para conteúdo qualquer é o rst-box, com o seu título como rst-box-head irmão logo antes.

list-grid

O vocabulário a sério das tabelas de dados: o cartão define as suas colunas uma vez e as linhas só escolhem células.

Os ecrãs empilham-se na vertical

Um ecrã é uma coluna: page-header, depois section-header + cartão, depois o section-header + cartão seguinte, por ordem de leitura. A disposição horizontal fica reservada às expressões que a trazem: rst-box-head, rst-field-row, rst-lbar, células rst-lrow, rst-seg-tabs.
