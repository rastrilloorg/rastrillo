トークン

各コンポーネントが自分を描くのに使うカスタムプロパティです。色と書体は テーマ（themes/plain.css）から、文字サイズの段階と余白の段階は構造として tokens.css から来ます。後者はどのテーマでも同じです。

ここに印字してあるのはライト側の値です。ダーク側は同じファイルに手で書かれていて、反転で作ることはありません。ui/contrast_test.go が両方の組の文書化された対をすべて WCAG 2.2 AA の下限 — 文字は 4.5:1、コントロールの境界線は 3:1 — に照らして守っています。色チップ自体は var() で塗られるので、あなたがいま読んでいる配色に従い、ダークモードでは印字された値と一致しません。

部品

ui が備えるすべてのテンプレート部品を、実際の画面が取らせる状態で並べています。どれもデータ値をちょうどひとつだけ受け取り、その場で dict を使って組み立てています。フォームは余白のある rst-box に、行は rst-list に入ります。部品がそう前提しているからです（下の「クラスの語彙」にある二つの規則を参照）。ギャラリーではどうにもならないことがひとつ。page-header と error-page はそれぞれ h1 を持つので、このページには h1 がいくつもあります。実際の画面ではちょうどひとつです。

クラスの語彙

部品にはなれない形。呼び出し側にしか分からない中身を包むからです。セクションカード、データグリッド、開閉メニュー、シェル自身の枠。クラスは tokens.css が出し、マークアップはアプリが書きます。以下はすべて ui.Styleguide が返す見本そのもので、ui のテストが tokens.css と突き合わせている見本です。コピーはここから。

box

余白のあるセクションカードと、その外側に置く見出しです。

どのカードがどれか

rst-list と rst-card に余白がないのは意図です。これらは行の連なりを収めるもので、余白は各行が自分で持ちます。フォームや段落、リンクの帯など、行でないものを直に入れると枠線にぴったり付いて描かれます。文字が縁に触れているのがその印です。任意の内容を入れる余白付きのカードは rst-box で、その見出しは直前に置く兄弟の rst-box-head です。
