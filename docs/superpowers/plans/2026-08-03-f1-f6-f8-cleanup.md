# F1 + F6 + F8 Cleanup Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close friction-log F1 (status slot on `list-row-action`), F6 (root index is a catch-all), and F8 (cwd-relative static serving) — library, generator, scaffold, and blog adoption.

**Architecture:** Three independent tracks. F6: `routeFor` emits `GET /{$}` for the root index; the blog drops its hand guard. F1: two flat optional keys on `list-row-action` render the existing `status-pill` in the row's right group; the blog's admin rows adopt it and `Sub` drops the status word. F8: the scaffold and the blog embed `static/` (`//go:embed` + `http.FileServerFS`) so the deployed single binary is self-contained; `rastrillo dev` watches `static/`.

**Tech Stack:** Go stdlib only. Go 1.25 module (`{$}` needs 1.22+; `http.FileServerFS` needs 1.22+).

**Spec:** `docs/superpowers/specs/2026-08-03-f1-f6-f8-cleanup-design.md` (approved).

## Global Constraints

- **As-built ui conventions:** PascalCase dict keys; contract comment above the define; every optional key guarded (absent key renders nothing); `rst-` class prefix; no catalog strings; zero JS.

- **Additive:** existing partials render byte-identically when new keys are absent; `Serve`/`Run` API untouched.
- **Formatting/computed strings in Go** (blog convention), never in templates.
