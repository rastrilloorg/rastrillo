# MCP for every app: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Rastrillo app can serve its exposed operations as MCP tools at `/api/v1/mcp`, under the same token check and policy as `/api/v1`, with authority checked again while each answer goes out.

**Architecture:**
- The API tree's request pipeline moves into an exported `api.Gate`, split into a per-request `Wrap` and a per-operation `Admit`.
- `Wrap` also buffers each answer and sends it in 64 KiB chunks. Before each chunk it reruns the checks that handlers registered with `api.Disclosed`.
- A new `mcp` package builds one stateless go-sdk server per request over a list of `op.Descriptor`s. It registers every tool, narrows `tools/list` per caller, and registers each call's or list's checks with the gate.
- The generator adds effect flags to descriptors and an MCP leg to the parity test.

**Tech Stack:**
- Go: `go 1.25.0` in go.mod, gate on Go 1.26.10.
- `github.com/modelcontextprotocol/go-sdk` v1.8.0.
- `github.com/go-json-experiment/json` (json v2, already a dependency).
- SQLite through `db`.

**Spec:** `docs/superpowers/specs/2026-10-25-mcp-design.md` (approved 2026-10-25). Section numbers below (§N) are the spec's.

## Global Constraints

- go-sdk pinned at exactly `v1.8.0`. No other new direct dependency.
- Limits:
  - `MaxResult` default 2 MiB (`2 << 20`).
  - `Gate.MaxResponse` default 2 MiB.
  - Emission chunk 64 KiB (`64 << 10`).
  - Each recheck-and-write cycle has a deadline of 5 s, shortened to the request's own.
  - `Gate.MaxBody` default 1 MiB.
- Tool name: descriptor ID with `.` replaced by `_`, matching `^[a-z][a-z0-9_]{0,63}$`.
- Fence verbs (§4), matched as a prefix of the ID's last `.`-part, on write descriptors only:
  `cancel refund revoke reject remove withdraw discard disconnect rotate regenerate replace delete send resend purge`.
- Generated flags:
  - create: `Destructive false`, `Idempotent false`.
  - update: `Destructive true`, `Idempotent false`.
  - delete: `Destructive true`, `Idempotent true`.
  - list and get: read, `Destructive false`, `Idempotent true`.
  - A replaced write body is always `Destructive true`, `Idempotent false`.
- `openWorldHint` is left unset. The cacheable hint is `private`. `tools.listChanged` is false.
- Endpoint: `/api/v1/mcp`. The scaffold and the examples mount it outside CSRF and sessions, beside `/api/v1`.
- Copy:
  - Every user- or agent-facing string comes from Task 1's approved copy, verbatim.
  - No em dashes as separators.
  - No new string ships without Paul's review.
- Repo rules:
  - Fail-first, as CONTRIBUTING.md:25 defines it: a compile failure isn't
    evidence. Each task's Step 2 first adds compiling stubs for its new
    names, returning zero values or `errors.New("not implemented")`. It
    then runs the new tests and records named assertion failures. Each
    task's report carries the before and after commands and their output.
  - Run `git` and `go run` tooling unsandboxed.
  - Locally `GOFLAGS=-mod=mod` for the three scratch-module packages.
  - Commit with `git commit --only <paths>` when other agents share the worktree.
  - Never `git add -A`.
- Code limits (main `7cb8e3ad`, `skill/code.md`). Read `skill/code.md` before writing code:
  - lines of 80 columns or fewer, with tab stops of 4;
  - non-test files of 400 lines or fewer, and non-test functions of 40 lines or fewer;
  - names spelled out, except `err`, `ctx` and `t`, `b`, `f` with their testing types: `response`, not `w`; `request`, not `r`; `descriptor`, not `d`. The signatures in this plan use short names only for brevity. Write them spelled out;
  - comments say why, in one or two sentences.
  Existing offences are recorded by identity in `.rastrillo/code.txt`, so a touched long line in `api/tree.go` must then fit. Records only go down. `make code` (`go run ./cmd/rastrillo budget code`) checks this, and every task runs it before committing. This is why Task 4 splits the tree's pipeline into `gate.go` and `emit.go`, and why `mcp` is several files.
- Budgets:
  - A package over its line budget fails `make budget`.
  - Raise a ceiling in `.rastrillo/budgets.txt` only with a stated reason, in the task that needs it.

## Review Focus

1. **Absent or `null` arguments.** A `tools/call` with no `arguments`, or `"arguments": null`, for a list tool should run the list with defaults, not refuse. Owner: Task 7, test `TestCallWithoutArguments`.
2. **Valid escaped surrogate pairs.** `"😀"` (a properly escaped emoji) must be accepted while a lone `"\ud83d"` is refused. A UTF-8 check that refuses every `\ud8xx` escape would refuse real text. Owner: Task 7, test `TestArgumentBytes`.
3. **Tool names that collide after `.`→`_`.** Resources `a_b` (op `a_b.create`) and a hand-written `a.b_create` give the same tool name. Boot must fail and name both IDs. Owner: Task 6, test `TestNewRefuses/duplicate_tool_name`.
4. **An app with nothing exposed.** `initialize` and `tools/list` succeed with an empty list. A `tools/call` is an unknown-tool protocol error, not a 500. Owner: Task 6, test `TestEmptyServer`.
5. **Two callers at once on one shared Ctx factory.** A read-only token and a writer listing concurrently each see only their own tools, with no cross-talk (`-race`). Owner: Task 6, test `TestListPerCallerConcurrent`.

```go
type Gate struct {
    Verify              Verifier
    Logger              *slog.Logger
    MaxBody             int64
    MaxResponse         int64 // zero means 2 MiB
    Before, After       []func(http.Handler) http.Handler
    RequireAgentSession bool
    Redact              func(string) string
}
func (c Config) Gate() Gate                 // MaxResponse zero
func (g Gate) Validate() error              // nil Verify, nil Before/After entries; api.New and mcp.New both call it
func (g Gate) Wrap(h http.Handler) http.Handler
func (g Gate) Admit(a rastrillo.Actor, o rastrillo.Operation) error
type Rechecker interface {
    Recheck(ctx context.Context, r *http.Request, was rastrillo.Actor) (rastrillo.Actor, error)
}
// Disclosed registers a check the gate reruns, with the fresh actor,
// before the headers and before each 64 KiB of this request's answer.
// Outside Wrap it does nothing.
func Disclosed(ctx context.Context, check func(ctx context.Context, fresh rastrillo.Actor) error)
// Refusal is Refuse without the write: it logs as Refuse does and
// returns the status and envelope.
func Refusal(r *http.Request, err error) (int, Error)
```

- `Admit` errors: `op.Forbidden{Reason: "read-only credential"}`, or an unexported error that `Refusal` maps to `invalid` with `msgAgentSession`. The order is the tree's: session first (`api/tree.go:318-329`).
- What `Wrap` does, in order:
  1. Stamp the logger, redactor and max body. Set no-store and the JSON content type. Wrap `r.Body` in `http.MaxBytesReader` at `MaxBody`, so a handler that never calls `Decode`, as MCP doesn't, is capped too. The SDK reads the body with an unbounded `io.ReadAll` (`mcp/streamable.go:478`).
  2. Recover panics.
  3. Run `Before`.
  4. Verify, with the 500 for an actor that has no credential or access.
  5. Read the agent headers, with the 422s.
  6. Put the actor on the context.
  7. Run `After`.
  8. Run the handler into the emission buffer, then emit.
- Emission, when `Verify` is a `Rechecker` (§3 steps 2-7):
  - Before the headers, and before each 64 KiB chunk, run one cycle under one deadline: 5 s, shortened to the request's own.
    1. `Recheck`.
    2. Compare `Subject`, `Agent`, `Credential` and the `Grant` fields `ID`, `Issuer`, `IdentityIssuer` and `Audience`. A mismatch is `ErrUnauthorized`.
    3. Copy the original's `Session` and `Harness` onto the fresh actor.
    4. Run every `Disclosed` check in registration order.
    5. Check `ctx.Err()` after each callback.
  - Then write the chunk with that deadline's remainder as its write deadline, and flush.
  - A failure before the headers becomes `Refusal`'s answer. After the headers, it is `panic(http.ErrAbortHandler)`.
  - If the transport can't set a write deadline, the answer is `unavailable`, before any data.
  - `Cache-Control: no-store` and `Content-Length` are set at commit, overriding whatever the handler set.
  - An answer over `MaxResponse` is `response_too_large`, status 422, with `msgResponseTooLarge` from Task 1.
- Without a `Rechecker`: the same buffering, cap and headers, and no checks.
- **The tree keeps its order:** Before, verify, agent headers, `Admit`, After, handler. A refused write never reaches `After`. `Wrap` is MCP's composition, which has no per-route `Admit`. The tree composes the same unexported steps with `Admit` between the agent headers and `After`. Both share one implementation of each step, so that `TestTreeAndGateAnswerAlike` compares like with like.
- In the tree's `handle`, after building `rc`, the tree registers its route's check: `Disclosed(ctx, func(ctx, fresh) error { if err := g.Admit(fresh, rt.Op.Operation); err != nil { return err }; c := rc; c.Actor = fresh; return op.Check(ctx, &c, rt.Op.Operation) })`.

- Produces:

```go
type Config struct {
    Gate         api.Gate
    Ctx          func(*http.Request) *rastrillo.Ctx
    Authorize    func(ctx context.Context, a rastrillo.Actor, o rastrillo.Operation) error
    Guard        op.ResponseGuard
    Guarded      bool
    Name, Version, Instructions string
    MaxResult    int
}

func ToolName(id string) string // "." → "_"
```

- `New` refuses, each with an error naming the descriptor:
  - a nil `Ctx` or `Authorize`;
  - whatever `Gate.Validate` refuses;
  - an empty ID or invalid `Access`;
  - an `Input` that isn't `{"type":"object",...}`;
  - a `Result` that is neither an object schema nor exactly `{"type":"null"}`;
  - a nil `Invoke`;
  - a `CheckFlags` failure;
  - a tool name that fails the regex;
  - a duplicate tool name, naming both IDs;
  - a `Guard` whose `Gate.Verify` isn't a `Rechecker`;
  - `Guarded` with no `Guard` or no `Rechecker`.
- `New` also sets its copy of the gate's `MaxResponse` to `3*MaxResult + 64<<10` when that is larger than the gate's own. The result appears twice in the answer, once as `structuredContent` and once as the text block. Escaping the text block can double it at most (every byte a `"` or `\`). So 3x the result plus the envelope always fits.
- Each tool:
  - Title is the description up to and including its first ". ", or all of it.
  - Description is `Description`, plus `"\n\n" + confirmLine + Confirm` when `Confirm != ""`.
  - Annotations, on every tool: `ReadOnlyHint: Access == Read`, `DestructiveHint: &Destructive` (false for reads), `IdempotentHint: Idempotent`. That is what Oficina's adapter sends (`O/mcp.go:22`), so Memoria's `notes_search`, a read with `Idempotent: true`, keeps its hint.
  - `OutputSchema` is `Result`, or nil for a null result.
- Tools are registered with the low-level `(*sdk.Server).AddTool(t, h sdk.ToolHandler)` (go-sdk v1.8.0 `mcp/server.go:302-315`). That one leaves input validation to the handler. The generic `sdk.AddTool` validates against the schema first (`mcp/server.go:400`), and would refuse `limit: 0` and `limit: 201`.
- The server: `ServerOptions{Instructions: instructionsText + "\n\n" + cfg.Instructions (when non-empty), Capabilities: &ServerCapabilities{Tools: &ToolCapabilities{ListChanged: false}}, SetCacheable: private}`, with the handler options `StreamableHTTPOptions{Stateless: true, JSONResponse: true}`.
- `tools/list`: a receiving middleware calls the SDK's own handler, then keeps only the tools whose descriptor passes `Admit` and `op.Check` for the caller. It freezes that slice and registers one `api.Disclosed` check that reruns `Admit` and `op.Check` for each frozen descriptor with the fresh actor, then `Guard(ctx, fresh, nil, nil, listResult)` when there is a guard. It recovers panics into an `internal` JSON-RPC error with a ref.

### Task 7: `mcp` tool calls

**Files:**
- Create: `mcp/call.go`, `mcp/call_test.go`
- Modify: `mcp/mcp.go` (register `call` as each tool's handler)

**Interfaces:**
- Consumes: Task 6's server and descriptors; `api.Refusal`, `api.Disclosed`, `Gate.Admit` (Task 4); `op.Check`.
- Produces: no new exported names.
- The call, in order (§6):
  1. Read the arguments. Absent or `null` become `{}`.
  2. Check the bytes. Refuse invalid UTF-8, or a `\uD800`-`\uDBFF` escape not followed by a `\uDC00`-`\uDFFF` escape, or a lone low surrogate, with an `invalid` tool error carrying `msgArgumentBytes`.
  3. Build `rc` as a copy of `cfg.Ctx(r)`, with `Actor` from the context and `Authorize = cfg.Authorize`. A nil `Ctx` result is an `internal` error.
  4. `Admit`.
  5. `Invoke(ctx, &rc, raw)`.
  6. Encode the result once with json v2, using a marshaler that writes `encoding/json.Number` as its literal digits. Over `MaxResult`, the answer is a tool error with `msgResultTooLarge`.
  7. Register `Disclosed`: `Admit` and `op.Check` for this descriptor with the fresh actor, then `Guard(ctx, fresh, &d, raw, result)` when there is a guard.
  8. Return `CallToolResult{StructuredContent: json.RawMessage(enc), Content: []Content{&TextContent{Text: string(enc)}}}`. For a null result, return `TextContent{"null"}` and no structured content.
- Steps 1 to 6 run under one `recover`. A panic becomes an `internal` tool error with the ref from `api.Refusal`.
- Any error from steps 3 to 6 becomes `IsError: true` with one text block, the JSON of `{"error": <api.Error>}` from `api.Refusal(r, err)`.
- Each call logs one line, `"mcp: call"`, with `tool` and the actor's `LogAttrs`, redacted, like the tree's `"api: request"`.
