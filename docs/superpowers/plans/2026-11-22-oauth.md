# OAuth for agents: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any Rastrillo app becomes the OAuth 2.1 authorization server for its own API and MCP doors, so Claude Code, Codex, claude.ai and ChatGPT connect by URL, with a person approving in the browser. Patrix's standalone sites adopt it.

**Architecture:** There is a new package, `oauth`. It owns client resolution (Client ID Metadata Documents, Dynamic Client Registration, loopback), the approval page's flow, codes, refresh tokens and connections.
- **Access tokens are `api_tokens` rows,** minted by `apitoken` with a `connection` column. The app's one verifier, `*apitoken.Store`, therefore checks both kinds and fills `Actor.Grant` through a hook.
- **The doors' 401 points at per-door metadata,** and the gate keeps a verifier's session for actors with a grant.

**Tech stack:**
- Go and SQLite (`migrate`);
- `net/http` ServeMux patterns;
- Rastrillo `api`, `mcp`, `apitoken`, `sessions`, `csrf` and `route`.

**Spec:** `docs/superpowers/specs/2026-11-22-oauth-design.md`, approved by Paul on 2026-11-22. Read it with this plan; every section number below (§) is the spec's.

## Global Constraints

- **The MCP authorization specification, version 2026-07-28,** is the contract (spec §5). Field names are exact:
  - `client_id_metadata_document_supported`;
  - `authorization_response_iss_parameter_supported`;
  - `code_challenge_methods_supported: ["S256"]`;
  - `token_endpoint_auth_methods_supported: ["none"]`;
  - `scopes_supported: ["read","write"]`.
- **Every OAuth answer carries `Cache-Control: no-store`.**
- **Lifetimes and limits:**
  - codes: single use, 60 seconds;
  - access tokens: 1 hour;
  - refresh tokens: 30 days after their last use, rotated on every use;
  - pending approvals: 10 minutes;
  - unused registrations: deleted after 30 days.
- **Document fetch:**
  - HTTPS only, to public addresses checked after DNS resolution;
  - no redirects;
  - 5-second timeout and a 64 KiB cap;
  - cached at most 24 hours, and failures never cached.
- **Redirects** are `https://` or loopback `http://` (`127.0.0.1`, `[::1]`, `localhost`). Matching is exact in every component (scheme, host literal, escaped path, query), except the port of a loopback host. Fragments are refused.
- **Errors.** Before the redirect address is trusted, problems get an error page, never a redirect. After that, errors redirect with `error`, `state` and `iss`.
- **Copy.** Every user-facing string goes through Luna (`codex exec -m gpt-6-luna`) and is recorded in the copy file of the repo it ships in.
- **Code style:**
  - 80 columns;
  - Go naming conventions;
  - comments only for why;
  - each directory within budget (`make budget`: 5,000 source and 8,000 test lines).
- **Gates.** Targeted tests while iterating (`go test ./oauth/... -run TestX`). Fleet CI runs the full suite. Locally set `GOFLAGS=-mod=mod`.

## Review Focus

1. **Unsafe document addresses.** A `client_id` URL that redirects, or resolves to a loopback, private or link-local address, is refused without the fetch reaching it (Task 4, `TestFetchRefusesUnsafeAddresses`).
2. **Changing who's signed in.** If the person signs out and someone else signs in between showing the page and approving, the POST is refused, because the pending approval is bound to the subject (Task 6, `TestApproveBoundToSubject`).
3. **Concurrent refresh.** Two refreshes racing with the same token: exactly one succeeds, the other is treated as reuse, and the connection ends (Task 7, `TestRefreshRaceEndsConnection`).
4. **Redirect addresses with a query string.** A registered `redirect_uri` that already has a query keeps it. The code, state and `iss` are appended, and `state` comes back byte for byte, including `&`, `=` and non-ASCII (Task 6, `TestRedirectKeepsQueryAndState`).
5. **Which door was called.** A 401 on `/api/v1/...` points at the `/api/v1` metadata, and one on `/api/v1/mcp` at the MCP metadata. Each document's `resource` equals the address that was called (Tasks 1 and 5, `TestChallengePerDoor`, `TestChallengeThroughTree`).

**Interfaces:**
- **Types** (`oauth/types.go`):

  ```go
  type Client struct {
      ID, Name     string
      Redirects    []string
      Document     bool // identified by a metadata document
      RegisteredAt, UsedAt time.Time
  }
  type Connection struct {
      ID, Subject, ClientID, ClientName, ReturnHost string
      Resource  string // the resource the person approved
      Access    rastrillo.Access
      Created, LastUsed time.Time
      Ended     *time.Time
  }
  type Pending struct {
      ID, Subject, ClientID, Redirect, Challenge, Resource, State string
      Return    string // the authorize GET's local path and query
      Requested rastrillo.Access
      Expires   time.Time
  }
  type Code struct {
      Hash []byte
      Connection, ClientID, Redirect, Challenge, Resource string
      Expires time.Time
  }
  type Refresh struct {
      Hash       []byte
      Connection string
      Expires    time.Time
  }
  var ErrNotFound = errors.New("oauth: not found")
  ```

- **Store** (the seam of spec §5.10):

  ```go
  type Store interface {
      SaveClient(ctx context.Context, c Client) error
      Client(ctx context.Context, id string) (Client, error)
      PruneClients(ctx context.Context, unusedSince time.Time) error
      SavePending(ctx context.Context, p Pending) error
      // Pending reads p without taking it; the same refusals as TakePending.
      Pending(ctx context.Context, id, subject string, now time.Time) (Pending, error)
      // TakePending deletes and returns p; ErrNotFound if absent,
      // expired at now, or another subject's.
      TakePending(ctx context.Context, id, subject string, now time.Time) (Pending, error)
      CreateConnection(ctx context.Context, c Connection, code Code) error
      Connection(ctx context.Context, id string) (Connection, error)
      ConnectionsOf(ctx context.Context, subject string) ([]Connection, error)
      EndConnection(ctx context.Context, id string, at time.Time) error
      // TakeCode deletes the code; used reports a code taken before
      // (kept as a tombstone until it expires).
      TakeCode(ctx context.Context, hash []byte, now time.Time) (code Code, used bool, err error)
      // RotateRefresh, in one transaction, retires old, stores next
      // and sets the connection's LastUsed to now; reused reports old
      // was retired already. Exactly one of two racing callers gets
      // reused == false, and a failure anywhere rolls back all three.
      RotateRefresh(ctx context.Context, old []byte, next Refresh, now time.Time) (c Connection, reused bool, err error)
      SaveRefresh(ctx context.Context, r Refresh) error
      RefreshConnection(ctx context.Context, hash []byte, now time.Time) (Connection, error)
  }
  func NewSQLStore(db *sql.DB) Store
  var Schema = migrate.MustFromFS(migrationFS, "oauth") // *migrate.Set: oauth_clients, oauth_connections, oauth_pending, oauth_codes, oauth_refresh
  ```

- **How the SQL store stays atomic.**
  - `TakeCode` claims the row with one statement that both checks and changes it: `UPDATE … SET used_at = ? WHERE hash = ? AND used_at IS NULL`, then reads it back.
  - `RotateRefresh` runs in one write transaction (`BEGIN IMMEDIATE`). It makes the same claiming `UPDATE` on the old row, inserts the next one, and updates the connection's `last_used`. Any error rolls back the whole transaction.

### Task 4: Clients: documents, registration and redirects

**Files:**
- Create: `oauth/fetch.go`, `oauth/redirect.go`, `oauth/clients.go`
- Test: `oauth/fetch_test.go`, `oauth/redirect_test.go`, `oauth/clients_test.go`

**Interfaces:**
- **Fetching documents.**
  - `type Fetcher struct`, with `NewFetcher() *Fetcher`. Its transport has `Proxy: nil`, so the dial check sees the destination, not a proxy. Its `net.Dialer.Control` refuses any address that isn't global unicast or is in a special-use range:
    - loopback, private, link-local and unspecified;
    - 100.64.0.0/10;
    - fc00::/7 and fe80::/10;
    - IPv4-mapped IPv6 forms of all of those;
    - 169.254.169.254.
  - Because the check runs at dial time, DNS rebinding can't get past it. Redirects are disabled, the timeout is 5 s, and bodies are capped at 64 KiB.
  - Test hooks, unexported and set in tests only, are the resolver, the dialer's address check and the root CAs.
  - `func (f *Fetcher) Fetch(ctx context.Context, url string) (Client, error)` validates `client_id == url`, a non-empty `client_name` and non-empty `redirect_uris`. Its cache is keyed by URL, honours `max-age` up to 24 h, and never caches a failure.
- **Matching redirects.** `func redirectAllowed(registered []string, requested string) bool`:
  - Every component must match exactly: scheme, host literal, path in its escaped form, and query.
  - The only exception is the port when the host is `127.0.0.1`, `[::1]` or `localhost`.
  - A fragment is refused.
  - So is any scheme other than `https`, or `http` to a loopback host.
- **Resolving and registering clients.**
  - `type clients struct { store Store; fetch *Fetcher; limit *limiter; now func() time.Time }`.
  - `func (c *clients) resolve(ctx context.Context, id string) (Client, error)`: an `https://` ID with a path goes through `Fetch`, and anything else through `store.Client`.
  - `func (c *clients) register(w http.ResponseWriter, r *http.Request)` accepts JSON with:
    - `client_name`;
    - `redirect_uris`, each passing `redirectAllowed`'s scheme and host rules;
    - `grant_types` ⊆ {authorization_code, refresh_token};
    - `response_types` ⊆ {code};
    - `token_endpoint_auth_method` "none" or absent.

    It refuses with `invalid_redirect_uri` or `invalid_client_metadata`, and answers 201 with `client_id` (22 random base62 characters) and the accepted metadata. It's rate-limited per `clientip.From` address to 10 a minute, in memory, with a 429 over that. It also prunes clients unused for 30 days, at most once an hour.

### Task 6: The approval page

**Files:**
- Create: `oauth/authorize.go`
- Test: `oauth/authorize_test.go`

**Interfaces:**
- **`GET /oauth/authorize`** runs spec §5.5's checks in order:
  1. Is the client known (`clients.resolve`)? If not, an error page.
  2. Does `redirectAllowed` pass? If not, an error page.
  3. Then `response_type=code`, `code_challenge_method=S256` with a challenge, `resource` one of the app's two, and `scope` in {read, write, read write, absent}. Each failure redirects with `invalid_request`, `invalid_target` or `invalid_scope`, plus `state` and `iss`.
  4. No session: 303 to `SignIn(<local path and query>, false)`.
  5. A stale session (`sessions.Fresh` false): 303 to `SignIn(…, true)`.
  6. `Allowed` false: an error page with its refusal text.
  7. Otherwise save the pending approval and render the approve page.
- **`POST /oauth/authorize`** takes form fields `pending`, `decision` ("approve" or "deny") and `access` ("read" or "write").
  - Before taking the pending approval, it reads it with `Store.Pending(id, subject)` and checks the session again: present, fresh and `Allowed`.
    - A stale session goes to `SignIn(p.Return, true)`, which brings the person back to the original authorize GET. That GET validates everything again and shows a fresh page; the old pending approval expires unused.
    - No session goes to `SignIn(p.Return, false)`.
    - Not `Allowed` gets the error page.
  - Then `TakePending(id, session subject)`.
  - Deny redirects with `access_denied`.
  - Approve sets access to the lower of what was requested and what was posted. It creates the connection, with `Resource` from the pending approval, and a code (a 32-byte random value, stored as a SHA-256 hash, expiring in 60 s) in one `CreateConnection`. Then it redirects with `code`, `state` and `iss`.
- **Building the redirect.** The registered redirect's own query is kept, and `code`, `state` and `iss` are added with `url.Values` encoding.

### Task 7: Tokens, refresh, revocation and connections

**Files:**
- Create: `oauth/token.go`, `oauth/revoke.go`, `oauth/connections.go`
- Test: `oauth/token_test.go`, `oauth/revoke_test.go`, `oauth/connections_test.go`

**Interfaces:**
- **`POST /oauth/token`**, form-encoded:
  - **`grant_type=authorization_code`** takes `code`, `code_verifier`, `client_id`, `redirect_uri` and `resource`.
    - The code must be live and unused. The S256 of the verifier must equal its challenge. The client, redirect and resource must equal the code's.
    - It answers `{"access_token","token_type":"Bearer","expires_in":3600,"refresh_token","scope"}`.
    - The access token comes from `Tokens.Mint(subject, MintInput{Agent: <client name through ValidAgentName, else "Agent">, Access, TTL: time.Hour, Connection})`. The refresh token is a 32-byte random value, stored hashed, expiring 30 days out.
  - **`grant_type=refresh_token`** takes `refresh_token`, `client_id`, and optionally `resource` and `scope`.
    - Before rotating, it reads the connection with `RefreshConnection` and checks that:
      - `client_id` equals the connection's;
      - `resource`, if sent, equals its resource;
      - `scope`, if sent, is no wider than its access;
      - `Allowed` holds.

      Failures answer `invalid_grant`, `invalid_target` or `invalid_scope` without touching the refresh token.
    - Then it calls `RotateRefresh`, mints, and touches the connection.
- **Reuse.** A reused code or a reused refresh token ends the connection: `EndConnection`, then `Tokens.RevokeConnection`. It answers `invalid_grant`.
- **`POST /oauth/revoke`** (RFC 7009) takes `token` and an optional `token_type_hint`.
  - An access token or a refresh token ends its whole connection, as spec §5.8 says.
  - An unknown token answers 200.
  - A storage failure answers 503 with `Retry-After`.
- **The person's view.**
  - `func (s *Server) Connections(ctx context.Context, subject string) ([]Connection, error)` lists live connections, newest first.
  - `func (s *Server) End(ctx context.Context, subject, id string) error` ends one of the subject's connections. Another person's ID gets `ErrNotFound`.
