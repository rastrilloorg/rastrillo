# 🤖 Base path Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A rastrillo app can be served whole under `/<slug>` on a shared product origin (`https://example.com/acme/…`): routes, assets, redirects and form actions. Its own direct hostname either redirects every request to the product path (the default) or, if the app opts in, serves a read-only public view at the root with no session.

**Architecture:** A new leaf package, `basepath`, holds one middleware that Serve installs outermost when `Options.BasePath` is set. It tells a product-path request from a direct-host request by the `Host` header, which the platform's edge preserves. On a product-path request it checks and strips `/<slug>`, puts the base on the request context, and rewrites root-relative `Location` and `Rastrillo-Location` headers on the way out. Bodies are explicit: Go code calls `basepath.Path(r, p)`, and templates call `{{path $ p}}`, which reads `Base` from the page data that `ui.ForRequest` fills. Generated code and the scaffold use both. The slug comes from `RASTRILLO_SLUG`, or from the instance's hostname label (`<slug>-<6 base32>`, spec §7.2 step 1) when `RASTRILLO_SLUG_FROM_HOST=1`.

**Tech Stack:** Go stdlib only (`net/http`, `net/url`, `path`, `regexp`). chromedp through the existing `harness` for the browser drive.

**Spec:** pegamento `docs/superpowers/specs/2026-09-27-user-models-design.md` on `design-user-models` (`db90b49`), §7.3 (tenant apps under a path), with §6.3 (one origin, one session), §7.2 (the version poll), §7.4 (same box) and §8. Roadmap: pegamento `docs/superpowers/plans/2026-09-28-user-models-roadmap.md`, Plan 5. First consumer: ppl `docs/superpowers/specs/2026-10-17-ppl-design.md` §4.2, §4.4, §9.2 (`d44b235`). Decision: Paul, 2026-10-17, rastrillo discussion #75: the direct host's behaviour is the app's choice.

## What the platform gives the app

Read from carlos/platform `origin/main` (`04819f9b`). The published CLI reference (`docs/site/cli.md`) does not document path routes, so this comes from the edge's code and the path-routing spec on main.

- **The prefix is not stripped.** "`ti.to/paulca/awesomeconf` arrives at Tito Go as `/paulca/awesomeconf`" (`docs/superpowers/specs/2026-09-02-path-based-routing-design.md:268-273`). The edge matches the first segment, cleaned and raw, by equality (`internal/edge/edge.go:1281-1300`), so `/acme` and `/acme/…` reach the tenant and `/acmex` never does.
- **`Host` is the hostname the visitor asked for**, on every proxy (`edge.go:2385`, `:2412`, `:2501`). A path-routed request carries the product's hostname (`internal/edge/cookiescope.go:93`). `X-Forwarded-Host` and `X-Forwarded-Proto` are set from the same request (`internal/edge/homemap.go:1119-1125`). No header names the matched prefix, and the app does not need one: `Host` plus the first segment say everything.
- **`X-Carlos-Version` is the target's release.** The edge stamps it on every response (`edge.go:2355-2363`), and on a path hit it is the tenant's release, not the hub's (`edge.go:1253`). That is Plan 4's fall-through check.
- **The app's own hostname is `CARLOS_HOST`** (`docs/site/cli.md:830`). Nothing tells the app the product hostname or its slug.
- **Platform calls arrive at the root, on a host that is not the product's.** The deploy and status probes `GET http://carlos/api/version` over the socket (`internal/release/versions.go:400`, `:429`). The activator's wake poll is `GET http://carlos/api/next-due` with `Authorization: Bearer $CARLOS_ADMIN_TOKEN` (`internal/activator/backend_exec.go:1706-1710`). Health probes send the route's own hostname (`internal/edge/prober.go:214`, `:480`). Scheduled ticks go to the instance's socket through `edge.UnixProxy` (`internal/host/schedule_wiring.go:350`), carrying the same bearer that `carlos.Tick` checks (`carlos/carlos.go:79-90` in this repo).
- **A provisioning credential cannot write per-instance config.** `PUT …/config` needs the `operate` role (`internal/console/authcli.go:842`). `POST …/instances` under the `instance` role can only bind an environment that already exists (`internal/console/apiinstances.go:1052`). So a hub cannot hand a new tenant its slug as config. This plan reads the slug from the hostname label instead. See "Platform request" below.

The scheme and locale cookies are the reader's preference across the product. Flash is taken by the next page of the same app. The only cookie that would collide harmfully is the session, and sign-in is refused.

2. **A slug that is also a route segment.** Slug `admin` with routes under `/admin/`: `/admin/admin/x` must reach `/admin/x`, and a redirect to `/admin/x` must leave as `/admin/admin/x`. Nothing may strip or prefix twice. Pinned in Task 1, `TestASlugThatIsAlsoARouteIsHandledOnce`.

4. **Redirects the app did not write.** `ServeMux`'s trailing-slash and clean-path 301s, `http.Redirect` with a relative target, and the locale middleware's own 301/308 all land under the base. Pinned in Task 3, `TestRedirectsTheAppDidNotWriteStayUnderTheBase`.

## Cross-plan interfaces

**Plan 4 (`provision`):**
- `GET https://<product>/<slug>/api/version` answers `200`, body `BuildVersion` as plain text (`serve.go:561-563`, unchanged), with response header **`X-Carlos-Version: <tenant app's release>`**, stamped by the edge (`edge.go:1253`, `:2363`). The hub's own value there means the prefix fell through (spec §7.4). A `200` also proves the right instance answered: an instance configured for another slug answers `404`.
- `GET https://<instance host>/api/version` and `/healthz` (spec §7.2 step 4) answer `200` at the root in both direct-host modes. They are never redirected.
- The tenant app's config, set once with `carlos env set --app <tenant-app>` before the first instance is created: `<APP>_ORIGIN=https://<product>` and `RASTRILLO_SLUG_FROM_HOST=1`.
- The label shape this plan parses is `<slug>-<6 chars of [a-z2-7]>` (`basepath.SlugFromHost`), with slug `[a-z0-9]`, inner hyphens allowed, at most 56 characters. If Plan 4 picks another shape, this function follows it.

**Plan 2 (`stateless-signin`):**
- `basepath.Original(r)` is the request URI exactly as the browser sent it, base and locale prefix included (`/acme/es/orders?x=1`). Build `next` for `/_carlos/refresh?next=<path>` from it.
- Redirect to the hub with an absolute URL (`https://<product>/_carlos/refresh?…`). A single-slash `Location` is treated as the tenant's own path and gets the base.
- `basepath.OnDirectHost(r)` true means signed out: the verifier must not accept the hub cookie there (it is host-only on the product origin anyway, so this is defence in depth).
- A tenant's verifier must not call `sessions.SignIn` or `Adopt`; under a base path they return `sessions.ErrPathRouted`.

- [ ] **Step 4: Implement `basepath.go`**

- Package doc says what the package is for and the two contracts from Global Constraints (headers carry app paths, bodies carry public paths), with why: the edge passes `/acme/…` unchanged (cite the path-routing spec §6), and one binary serves every tenant, so routes stay root-relative and the prefix is per process.

- `FromEnv` reads `RASTRILLO_SLUG`, `RASTRILLO_SLUG_FROM_HOST` (only `"1"` counts as set) and `CARLOS_HOST` through `getenv`. It returns `Config{}` with no error when neither slug variable is set, and calls `Validate` before returning. Comment why the host form is opt-in: an ordinary app whose label happens to end in six base32 letters must not move under a path.
- `Validate`: `Origin` parses as `http` or `https` with a host, and its path, query and fragment are empty. `Slug` matches the label-slug pattern above. Errors start with `rastrillo/basepath: ` and say what to set.
- Context keys are unexported struct types. `Base`, `Original` and `OnDirectHost` read them, and default to `""`, `r.URL.RequestURI()` and `false`.
- `Path(r, p)`: returns `p` unchanged when the base is empty, or when `p` does not start with exactly one `/`, or starts with `/\`. Otherwise `p == "/"` or `p[1]` in `?#` gives `base + p[1:]`, and anything else gives `base + p`.

- [ ] **Step 5: Implement `handler.go`'s product-path branch**

`Handler` decides `product := sameHost(r.Host, c.Origin)`. Direct hosts are Task 2. For now, a non-product host calls `next` unchanged.

`sameHost` lowercases both, drops one trailing `.` from `r.Host`, and drops `:443` for an https origin or `:80` for an http origin. It never reads `X-Forwarded-Host`, and the comment says why: the edge preserves `Host` (`edge.go:2385`), and a header a client can send must not choose the app's base.

On the product host:
1. `clean := cleanPath(r.URL.Path)`, which is `path.Clean` with a trailing slash kept, the way `net/http`'s `ServeMux` cleans.
2. If clean's first segment is not exactly `c.Slug`, answer `http.NotFound`. The comment: this instance answers only for its own slug, and fails closed when a path map points elsewhere. That is also what makes Plan 4's 200 mean "the right instance".
3. If `clean != r.URL.Path`, redirect to `clean` plus the query: 301 for GET and HEAD, 308 otherwise (the locale middleware's reason, `localemw.go:41-51`). Write this `Location` directly, not through the rewriting writer: it is already public.
4. Strip: a shallow copy of the request and its URL, the way `localemw.go:66-96` does. `Path` becomes the rest, or `/` when nothing is left. `RawPath` is trimmed only when it literally starts with `"/"+slug+"/"`, and is cleared otherwise; copy that block's comment reasoning. Store the base (`"/"+slug`) and `Original` (the received `r.URL.RequestURI()`) on the context.
5. Serve `next` with a `*rewriter` around `w`.

`rewriter` embeds `http.ResponseWriter` and holds `base` and a `done` flag. `fix()` rewrites `Location` and `Rastrillo-Location` with the `Path` rule. It runs once, at the first `WriteHeader`, `Write` or `Flush`. 1xx statuses fix the header too but do not set `done`. It has `Unwrap`, `Flush` and `FlushError`, and `Hijack`, each going through `http.NewResponseController(w.ResponseWriter)`. Model it on `perf/perf.go:296-460` and say so in a comment. The comment on `rewriter` names the redirects no app code writes (`ServeMux`'s trailing-slash and clean-path 301s, `http.Redirect`'s resolution of a relative target against the stripped path) as the reason this is a writer and not a helper every caller must remember.

- [ ] **Step 6: Implement `basepathtest.Leaks`**

Match attribute values with ``(?i)\b(href|src|action|formaction|poster|data-[a-z0-9-]+)\s*=\s*("([^"]*)"|'([^']*)')``. A value is a leak when it starts with one `/` (not `//`) and is not `base`, and does not start with `base+"/"`, `base+"?"` or `base+"#"`. Return each leak as it appears in the source (`name="value"` with its own quotes). With `base == ""`, return nil. # 🤖 basepath

````markdown
Use `basepath` to serve your app under a path on another app's domain, such as `https://example.com/acme`. A hub product does this: the hub is at the root, and each tenant is an instance at `/<slug>`.

Set two variables on the tenant app, once:

```sh
carlos env set --app tenant TENANT_ORIGIN=https://example.com RASTRILLO_SLUG_FROM_HOST=1
```

Each instance then reads its slug from its own hostname, `acme-x7k2pq.<account>.oncarlos.com`, and serves everything under `/acme`.

In templates, write links with `path`: `<a href="{{path $ "/orders"}}">`. In Go, use `basepath.Path(r, "/orders")` for anything that goes into a page. Redirect as usual, with `http.Redirect(w, r, "/orders", http.StatusSeeOther)`: the base is added for you. To send someone to the hub, use a full URL.

The instance's own hostname sends every visitor to `https://example.com/acme/…`. To show a public page there instead, with nobody signed in, set `opts.BasePath.DirectHost = basepath.ServeDirect`.

To try it locally, run `RASTRILLO_SLUG=acme rastrillo dev` and open `http://localhost:8080/acme`. `http://127.0.0.1:8080` is then your direct host.

Check your own pages with `basepathtest.Leaks(body, "/acme")`. It lists every link that would leave your app.
````
