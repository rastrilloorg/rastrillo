# 🤖 Base path Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A rastrillo app can be served whole under `/<slug>` on a shared product origin (`https://example.com/acme/…`): routes, assets, redirects and form actions. Its own direct hostname either redirects every visitor to the product path (the default) or, if the app opts in, serves a read-only public view at the root with no session.

**Architecture:** A new leaf package, `basepath`, holds one middleware that Serve installs outermost when `Options.BasePath` is set. It tells a product-path request from everything else by the `Host` header, which the platform's edge preserves. On a product-path request it checks and strips `/<slug>` (leaving `r.RequestURI` as the browser sent it), puts the base on the request context, and rewrites root-relative `Location` and `Rastrillo-Location` headers on the way out. Bodies are explicit: Go code calls `basepath.Path(r, p)`, and templates call `{{path $ p}}`, which reads `Base` from the page data that `ui.ForRequest` fills. Platform calls (socket requests on `Host: carlos`, probe paths, ticks) are never redirected. On a served direct host the framework refuses writes. Sign-in, the row-backed session store and the flash cookie are made safe for one shared origin. The slug comes from `RASTRILLO_SLUG`, or from the instance's hostname label (`<slug>-<6 base32>`, spec §7.2 step 1) when `RASTRILLO_SLUG_FROM_HOST=1`.

**Tech Stack:** Go stdlib only (`net/http`, `net/url`, `path`, `regexp`). chromedp through the existing `harness` for the browser drive.

**Spec:** pegamento `docs/superpowers/specs/2026-09-27-user-models-design.md` on `design-user-models` (`db90b49`), §7.3 (tenant apps under a path), with §6.3 (one origin, one session), §7.2 (the version poll), §7.4 (same box) and §8. Roadmap: pegamento `docs/superpowers/plans/2026-09-28-user-models-roadmap.md`, Plan 5. First consumer: ppl `docs/superpowers/specs/2026-10-17-ppl-design.md` §4.2, §4.4, §9.2 (`d44b235`). Decision: Paul, 2026-10-17, rastrillo discussion #75: the direct host's behaviour is the app's choice.

## What the platform gives the app

Read from carlos/platform `origin/main` (`04819f9b`). The published CLI reference (`docs/site/cli.md`) does not document path routes, so this comes from the edge's code and the path-routing spec on main.

- **The prefix is not stripped.** "`ti.to/paulca/awesomeconf` arrives at Tito Go as `/paulca/awesomeconf`" (`docs/superpowers/specs/2026-09-02-path-based-routing-design.md:268-273`). The edge matches the first segment, cleaned and raw, by equality (`internal/edge/edge.go:1281-1300`), so `/acme` and `/acme/…` reach the tenant and `/acmex` never does. A miss falls through to the hostname's own route (`edge.go:1238`).
- **`Host` is the hostname the visitor asked for**, on every proxy (`edge.go:2385`, `:2412`, `:2501`). A path-routed request carries the product's hostname (`internal/edge/cookiescope.go:93`). `X-Forwarded-Host` and `X-Forwarded-Proto` are set from the same request (`internal/edge/homemap.go:1119-1125`). No header names the matched prefix, and the app does not need one: `Host` plus the first segment say everything.
- **`X-Carlos-Version` is the serving route's release**: the target's on a path hit, the hostname's own on a fall-through (`edge.go:1238-1254`, `:2355-2363`). It names a release, not an instance.
- **The app's own hostname is `CARLOS_HOST`** (`docs/site/cli.md:830`). Nothing tells the app the product hostname or its slug.
- **Platform calls to the instance socket use the placeholder `Host: carlos`.** The wake readiness check is `GET http://carlos/`, accepting any status under 500, with a client that follows redirects (`internal/activator/backend_exec.go:3218-3240`). The wake-time poll is `GET http://carlos/api/next-due` with `Authorization: Bearer $CARLOS_ADMIN_TOKEN` (`backend_exec.go:1706-1710`). A claim's readiness probe requests the manifest's `ready_path`, `/` by default, on `http://carlos` and wants a 2xx (`internal/host/claimready_linux.go:40-60`, `internal/provision/provision.go:310`). Scheduled ticks reach the socket through `edge.UnixProxy` with the admin bearer (`internal/host/schedule_wiring.go:350`; `carlos/carlos.go:79-90` here). The edge cannot route a visitor's `Host: carlos` anywhere, so that host is the platform's own.
- **Health probes on TCP upstreams are configurable.** The edge prober takes `Health.Path` (default `/`) and `Health.HostHeader` (default the route's hostname) and wants the configured status (`internal/edge/prober.go:193-214`, `:480`, `:492`). These are operator-set routes; the plan states what a path-routed tenant's probe must be.
- **`internal/release/versions.go`'s JSON version helpers have no callers on main** (they decode `{"build": …}`; rastrillo answers plain text). They are not the deploy check, and nothing here depends on them.
- **A provisioning credential cannot write per-instance config.** `PUT …/config` needs the `operate` role (`internal/console/authcli.go:842`). `POST …/instances` under the `instance` role can only bind an environment that already exists (`internal/console/apiinstances.go:1052`). So a hub cannot hand a new tenant its slug as config. This plan reads the slug from the hostname label instead. See "Platform request" below.

- **Off means unchanged.** With `Options.BasePath` zero, no middleware is installed, `basepath.Path` returns its argument, and every existing test passes untouched. The one deliberate API change is `flash.Set`, which gains the request (Task 6).
- **`r.RequestURI` is never changed.** The strip copies the request and edits only `r.URL`, as `http.StripPrefix` does. `basepath.Original(r)` returns the same string. Plan 2 builds `next` and its hub `return_to` from it.
- **Headers carry app paths; bodies carry public paths.** A `Location` or `Rastrillo-Location` that starts with exactly one `/` is the app's own path, and the middleware adds the base, once. An absolute `Location` (`https://…`) is never touched: that is how an app leaves itself, and Plan 2's redirects to the hub's `/_carlos/refresh` rely on it. `Rastrillo-Location` is same-app only: `ui/rastrillo.js:66-69` follows only a local path, on purpose. Never pass `basepath.Path` output to `http.Redirect`: it would be prefixed twice. One known gap: `http.Redirect` writes a fallback HTML link in the body from its argument, so that link lacks the base; browsers follow the header.
- **Every root-absolute URL in a body goes through `basepath.Path` or `{{path $ …}}`.** Hidden `return`/`return_to` values stay app paths, because the server turns them into `Location`.
- **No tenant sign-in under a base path or on a direct host.** Spec §6.3: "Tenants verify, never mint". Every sign-in plugin keys on the bare origin every tenant shares (one WebAuthn RP ID, one Keymail `client_id`, root-scoped `__Host-` cookies), so making them path-aware is a security design, not a prefix change. Task 7 makes their entry points answer 404 there, before any mail, row or cookie. The row-backed `sessions` store is inert there (Task 5). Plan 2's signed mode, when it lands, governs its own behaviour under a base path.
- **Cookie paths.** The scheme and locale cookies keep `Path=/`: they are the reader's preference across the product, and one origin is one browser security boundary anyway (spec §3 C). The flash cookie is named for the slug and scoped to the base path (Task 6), because a hub or sibling request, a prerender included, could otherwise take a tenant's notice, and a tenant would show the hub's root notice on every page it could not clear.
- **`csrf` is unchanged.** `Sec-Fetch-Site: same-origin` cannot tell sibling tenants apart. Spec §3 C and §8.4 accept that: model C only where every tenant runs the app's own code.
- **A path-routed tenant's TCP health probe**, where an operator sets one, uses path `/healthz` or `/api/version` with the instance's own host (the default) or `HostHeader: carlos`. With `HostHeader` set to the product host, the path must be `/<slug>/healthz`: anything else on the product host is outside the base and answers 404. Socket probes need nothing: they arrive on `Host: carlos`.
- **A platform call is never redirected off the socket.** Session guards (`sessions.Require`, `auth.RequireSession`) answer a platform call with 403 rather than a redirect to the product URL, because the wake check's client would follow it into TLS. A tenant whose `/` is behind a session declares `ready_path = "/healthz"` in its manifest's `moves` (`internal/provision/provision.go:295-312`), because a claim's readiness probe wants a 2xx.

Task 10's front handler mimics the edge's routing in-process (prefix map, fall-through to a hub, `X-Carlos-Version` per route); it shows the tenant's side, not the edge's. Plan 7's approved end-to-end run in `demo` exercises a real path route. If Paul wants one sooner, scope it then, on the model of discussion #61.

## Review Focus

1. **Platform calls on the direct host in redirect mode.** The wake check `GET /` on `Host: carlos` (whose client follows redirects into a TLS handshake on a plain socket), `GET /healthz` on the instance's own host, `/api/version`, `/api/next-due`, a claim's readiness path and a scheduled tick must be answered at the root, never sent a 307. Otherwise wakes, deploys and moves fail. Pinned in Task 2, `TestDirectHostAnswersPlatformCallsAtTheRoot`, and Task 3, `TestPlatformRoutesAnswerOnTheDirectHost`.
2. **A slug that is also a route segment.** Slug `admin` with routes under `/admin/`: `/admin/admin/x` must reach `/admin/x`, and a redirect to `/admin/x` must leave as `/admin/admin/x`, not stripped or prefixed twice. Pinned in Task 1, `TestASlugThatIsAlsoARouteIsHandledOnce`.
3. **Unclean, encoded and lookalike paths.** `//acme/x` and `/acme/./x` are sent to `/acme/x` with encoded bytes kept (`%2F`, `%3F`, `%23` stay escaped). `/acme/../bob`, `/acmex`, `/ACME/x`, `/%61cme/x` and `/` on the product host are 404. Pinned in Task 1, `TestUncleanPathsAreCanonicalOrRefused` and `TestProductPathIsStripped`.
4. **Redirects the app did not write.** `ServeMux`'s trailing-slash and clean-path 301s, `http.Redirect` with a relative target, the locale middleware's own 301/308, and a handler that sets `Location` and returns without writing all land under the base. Pinned in Task 1, `TestHeadersAreRewrittenOnce`, and Task 3, `TestRedirectsTheAppDidNotWriteStayUnderTheBase`.
5. **Streaming and 1xx through the rewriting writer.** A jobs event stream under a base path, behind `perf`'s own writer, must still flush; a 103 then a 303 must not prefix twice. Pinned in Task 1, `TestRewritingWriterKeepsFlushHijackAndUnwrap` and `TestInformationalResponsesDoNotPrefixTwice`, and Task 4, `TestJobEventsStreamUnderABasePath`.

## Cross-plan interfaces

**Plan 4 (`provision`), from its plan's "What this plan assumes of Plan 5":**
- `GET https://<product>/<slug>/api/version` reaches the framework's own `/api/version` handler (`serve.go:561-563`) and answers `200` with that handler's headers and body. Pinned in Task 3, `TestFrameworkRoutesAnswerUnderTheBase`.
- On the direct host, `GET /api/version` and `GET /healthz` are never redirected, in either mode. Pinned in Task 2 and Task 3.
- Plan 4 adds `Options.NameInstance`, which makes `/api/version` send `Rastrillo-Host: $CARLOS_HOST`. This plan does not add it. The rewriting writer touches only `Location` and `Rastrillo-Location`, so the header passes through unchanged (Task 1, `TestOtherHeadersPassThrough`). `Rastrillo-Host`, not this plan's 404 for a foreign slug, is what proves which instance answered: two instances can share a slug (`<slug>-<random>`).
- The edge stamps `X-Carlos-Version` (`edge.go:1238-1254`); this plan neither sets nor strips it.
- The tenant app's config, set once with `carlos env set --app <tenant-app>` before the first instance is created: `<APP>_ORIGIN=https://<product>` and `RASTRILLO_SLUG_FROM_HOST=1`. The label shape this plan parses is `<slug>-<6 chars of [a-z2-7]>` (`basepath.SlugFromHost`), slug `[a-z0-9]` with inner hyphens, at most 56 characters. If Plan 4 picks another shape, this function follows it.

**Plan 2 (`stateless-signin`), from its plan's "Cross-plan interfaces":**
- `r.RequestURI` is left as the browser sent it, base and locale prefix included (`/acme/es/orders?x=1`). Pinned in Task 1, `TestProductPathIsStripped`. `basepath.Original(r)` returns the same value.
- Absolute `Location` headers are never rewritten. Pinned in Task 1, `TestHeadersAreRewrittenOnce`.
- `basepath.OnDirectHost(r)` true means signed out. Plan 2's signed verifier should check it; the hub cookie is host-only on the product origin, so this is defence in depth.
- Task 5's inertness applies to the row-backed store (`Config.Signed == nil` once Plan 2 lands). A signed tenant verifies under the base path. Whichever plan lands second adds that condition and its test.
- Task 7 refuses `auth` and the other plugins under a base path. Plan 2's tenant mounts none of them; its hub runs them at the root.
