# Compiled templates, phase 1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apps keep writing `html/template`; `rastrillo generate` compiles every page to Go that renders byte-identical HTML at least 3x cheaper, with `html/template` as the fallback whenever there is doubt.

**Architecture:** A drop-in set type (`tmpl.Template`) wraps `html/template` and, on first execution, fingerprints each template and binds compiled code registered under that fingerprint. Compiled code comes from `rastrillo generate`, which runs the app's startup in capture mode, escapes the captured trees with a fork of the stdlib escaper, compiles them (typed where it can infer types, dynamic otherwise), and writes one generated file into each package that builds template sets.

**Tech Stack:** Go 1.26 (`text/template/parse`, `go/types`, `golang.org/x/tools/go/packages` — already in `go.mod`), `html/template` as oracle.

**Spec:** `docs/superpowers/specs/2026-10-29-compiled-templates-design.md`. Read it first; this plan argues from it and does not restate its reasons. Phases 2 (formatting) and 3 (`dict` specialisation) get their own plans after Task 10's gate.

- `GOTOOLCHAIN = go1.26.10` (Makefile). The fork in Task 2 is copied from go1.26.10's `src/html/template` (locally `/home/paulca/.local/go-dist/src/html/template`).
- `go.mod` stays at `go 1.25.0`; no new module dependencies.
- Locally run Go with `GOFLAGS=-mod=mod` and with the Bash sandbox off (module cache is read-only inside it); run git unsandboxed.
- Output of the compiled path is **byte-identical** to `html/template` for the same set and data in phase 1. Errors occur in the same cases; error text and partial output before an error are not contracts.
- Never weaker escaping, never stale HTML, never a render failure `html/template` would not have had (spec "Anti-goals").
- App authors change nothing: no annotations, no type declarations, no template edits.
- Names fixed by this plan: package `amadan.net/rastrillo/rastrillo/tmpl`, runtime package `.../tmpl/tmplrt`, fork `.../tmpl/internal/escape`, compiler `.../internal/tmplc`, orchestrator `.../internal/tmplgen`; generated file `rastrillo_templates_gen.go`; build tag `rastrillo_capture`; env vars `RASTRILLO_TEMPLATE_CAPTURE`, `RASTRILLO_TEMPLATE_SHADOW`, `RASTRILLO_DEV`.
- Every user-facing string (generate's output lines, log warnings, reference docs) goes through the copy-review skill before it lands; batch them in Task 9.
- New Go tests run in the existing sharded suite automatically; a new non-`go test` check needs a SUITE role and a bumped `@N` in the suite filename.
- Commit from the `compiled-templates` worktree with `amadan commit`.

## Review Focus

1. **Stringers and named string types.** A value whose type has `String()` (or is a named string type like the bake-off's `filter`) must print exactly as `html/template` prints it; a fast path that treats it as a plain `string` is wrong. Test in Task 1 and Task 8.
2. **Pointer-receiver methods on non-addressable data.** `html/template` cannot call a pointer-receiver method on a struct passed by value at top level or held in a map, but can on a slice element. Typed Go code calls it everywhere. The compiled path must error where `html/template` errors. Test in Task 8.
3. **Function errors and panics.** A FuncMap function returning a non-nil `error`, or panicking, fails the execution in `html/template` (panics are recovered into errors). Compiled code must do the same, not crash the request. Test in Task 7.
4. **Concurrent first execution.** Many goroutines executing a fresh set at once must fingerprint and bind exactly once, with no race, and none may run `html/template` before fingerprinting (escaping mutates the trees). Test in Task 3.
5. **Data of an unexpected shape.** `*view` vs `view`, a nil `*view`, or a different type than generate inferred must take the dynamic path or fall back, never a wrong typed path. Test in Task 8.
